# 实时竞拍大师 — 项目文档

## 一、项目概述

实时竞拍大师是一个基于 Go + React 的在线直播竞拍系统，支持商家创建直播间按序拍卖商品、用户实时出价、系统自动成交。项目架构从"以商品为中心"重构为"以商家/直播间为中心"，并实现了四层账号安全体系。

**技术栈**

| 层 | 选型 | 版本 |
|---|---|---|
| 后端框架 | Gin | v1.9 |
| 数据库 | MySQL (GORM) | 8.4 |
| 缓存 | Redis | 3.0+ |
| WebSocket | gorilla/websocket | v1.5 |
| 认证 | JWT (golang-jwt) | v5 |
| 配置 | Viper | v1.18 |
| 前端 | React + TypeScript + Vite | 18+ |
| 状态管理 | Zustand | — |
| 管理后台 | React + Ant Design 5 | — |
| 动画 | Framer Motion | — |

**项目亮点**

- Redis Lua 脚本实现原子出价，解决高并发竞态
- Go Channel 队列串行化单商品出价，保证顺序一致性
- WebSocket 房间广播 + 异步 DB 写入，读写分离
- JWT 双 Token 机制 + RBAC 三级角色 + 接口限流

## 三、核心设计

### 3.1 竞拍状态机

**状态定义**

```
NOT_STARTED ──START──▶ ONGOING ──TIMEOUT──▶ ENDED
     │                    │
     └──（任意状态可）────CANCEL──▶ CANCELLED
```

- `NOT_STARTED`：商品已创建，等待开始
- `ONGOING`：竞拍进行中，接受出价
- `ENDED`：倒计时归零，自动成交
- `CANCELLED`：商家手动取消

状态数据通过 JSON 序列化存储在 Redis 中，key 格式：`auction:master:auction:state:<goodsId>`。服务重启后从 Redis 恢复状态，实现无状态可恢复。

### 3.2 出价原子化

出价流程采用三层设计保证高并发下的正确性：

**（1）队列串行化**：每个商品一个 Go Channel 队列（buffer 2048），所有出价请求进入同一队列，单 goroutine 顺序消费，天然避免同一商品的竞态。

**（2）Redis Lua 原子操作**：出价脚本在 Redis 服务端原子执行——校验状态、检查自抬价、计算新价格、更新参与人数、持久化，一步完成。关键校验逻辑：
- 竞拍必须是 ONGOING 状态
- 同一用户不能连续出价（防自抬）
- 达到封顶价即结束拍卖

**（3）异步写入 MySQL**：出价成功后立即通过 Worker 池异步写 BidRecord，不阻塞出价主流程。

**（4）双通道广播**：
- 每次成功出价 → `price-updated` 事件立即广播
- 每 100ms → `price-sync` 定时同步当前价格和倒计时

### 3.3 直播间架构

系统从最初的"以商品为中心"重构为"以商家/直播间为中心"：

| 对比维度 | 旧架构 | 新架构 |
|---|---|---|
| 房间标识 | `auction:<goodsId>` | `room:<userId>` |
| 首页 | 商品列表 | 直播间卡片网格 |
| 商品切换 | 页面跳转 | 同房间内无缝切换 |
| 出价面板 | 全屏弹出 | 聊天区侧边栏展开 |
| 多商品管理 | 独立展示 | 按场次排序，自动推进 |

同一商家同时只能有一个进行中竞拍，结束后 10 秒自动开始下一商品。

### 3.4 账号安全四层体系

| 层次 | 内容 | 实现 |
|---|---|---|
| L1 基础防护 | bcrypt 密码哈希、登录限流（5 次/15min） | Redis 计数 + TTL |
| L2 会话安全 | JWT 双 Token（access 15min + refresh 7day）、refresh 一次性轮换、登出黑名单 | Redis 黑名单 + jti |
| L3 权限隔离 | RBAC 三级角色（admin/merchant/user）、Gin 中间件校验 | RequireRole 中间件 |
| L4 纵深防御 | 出价限流（1s/2次）、登录限流（1s/5次）、CORS 白名单 | Redis 滑动窗口 |

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/auth/register` | 注册 |

| POST | `/api/auth/refresh` | 用 refreshToken 换新 token 对 |
| POST | `/api/auth/logout` | 登出，accessToken 加入黑名单 |

#### 竞拍（商家+管理员）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/auctions` | 创建竞拍商品 |

| POST | `/api/auctions/:id/start` | 开始竞拍 |
| POST | `/api/auctions/:id/cancel` | 取消竞拍 |
| PUT | `/api/auctions/:id` | 编辑竞拍（仅未开始） |
| PUT | `/api/auctions/reorder` | 调整排序 |

#### 竞拍（所有用户）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/auctions` | 竞拍列表（支持 ?userId= 过滤） |
| GET | `/api/auctions/:id` | 竞拍详情 |
| GET | `/api/auctions/sequence` | 竞拍序列（ongoing/upcoming/ended） |
| GET | `/api/merchants/rooms` | 直播间列表 |
| POST | `/api/bid` | 出价 |

#### 订单 & 其他

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/orders` | 全部订单 |
| GET | `/api/orders/me` | 我的订单 |

### 4.2 WebSocket 事件

**客户端 → 服务端**

| 事件 | 数据 | 说明 |
|---|---|---|
| `join-merchant-room` | userId (int) | 加入直播间 |
| `leave-merchant-room` | userId (int) | 离开直播间 |
| `bid` | goodsId (int) | 出价 |

**服务端 → 客户端**

| 事件 | 说明 |
|---|---|
| `joined-room` | 加入房间确认，附带当前拍品状态 |
| `auction-state` | 完整竞拍状态快照 |
| `price-updated` | 出价成功后广播（价格/倒计时/排名） |
| `price-sync` | 每 100ms 定时同步 |
| `timer-sync` | 每 2s 倒计时同步 |
| `auction-ended` | 拍卖结束，附带赢家/成交价/订单号 |
| `auction-started` | 下一场自动开始通知 |
| `next-auction` | 10 秒倒计时预告 |
| `outbid` | 被超越通知 |
| `bid-error` | 出价失败原因 |
